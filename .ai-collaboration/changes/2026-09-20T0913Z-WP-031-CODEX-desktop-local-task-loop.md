Packaging binaries are Git-ignored and live in `package/`.
- Mapping: REQ-009/REQ-018 → WP-031 → AC-031. The prior desktop only persisted queued tasks. The desktop now starts a local poller with a single built-in, no-target-access diagnostic plugin. An authenticated plugin catalog lets the UI present only installed options; unknown plugins are rejected on creation. Scope, approvals and emergency-stop registries are shared with the worker. Legacy invalid tasks become visibly failed rather than blocking the queue.
- Decision: this release candidate deliberately does not register external or high-risk tool plugins in the desktop process. The local diagnostic is a bounded end-to-end proof, not a substitute for the unpublished Agent. Redis/Docker remain optional server-side backends.
- TDD: desktop integration and React submission tests failed first because the plugin endpoint/form and worker were absent, then passed. The integration test confirms status, attempts, JSONL event sequence, rejection of unknown plugins, legacy-task failure/recovery, and live scope enforcement.
- Validation: 116 Python tests passed, 2 Linux-only skipped; 8 frontend tests passed. Ruff, strict mypy (26 files), Vite build, fresh PyInstaller build, frozen `--self-test` exit 0, source-vs-bundle starfield SHA-256 match, and Inno Setup 7.1 compile exit 0. `docs/TEST_REPORT.md` contains public-beta test scope.
- Limitations: no clean-machine missing-component installation, full Linux installation, complete Agent distribution, or external provider acceptance yet. The public beta must label these limits. No third-party tool executable or local Agent bundle is staged for GitHub.
